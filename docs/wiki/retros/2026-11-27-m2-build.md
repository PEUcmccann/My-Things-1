# Retro: Milestone 2 build (2026-11-27)

Retro on two M2 implementer sessions, chosen because they needed the most rework: the #29 implementer and the code-review fixer. The owner asked for it ("Run the retro"). It was run with `anthropic-skills:retro` by a delegated subagent; its report lived in the chief-of-staff session and is not copied here.

## Findings, most severe first, and what was done on 2026-11-27

1. **The coordinator's brief narrowed #29's scope, and the coordinator merged a report that listed the gaps.**
   - The brief said "keep your core changes to the series-edit logic and the detail screen". The #29 ticket's criteria also covered bulk edits, Sub-to-do row edits and a rule start-date control.
   - The implementer reported the gaps. The coordinator merged anyway, and the milestone code review found them again.
   - **Done:** `docs/agents/implementer-brief.md` defines "done" as every acceptance criterion and Decision, and asks for a done/not-done checklist in each report. Before merging, the coordinator now compares that checklist with the ticket.
   - **Offered to the user, not done:** adding the same rule to the chief-of-staff skill.
2. **Nothing enforced "core tests go through actions and queries only" (CLAUDE.md).** Three implementers (#25–#27) tested `parseRrule` directly or asserted the stored `repeat.rrule`. **Done:** an ESLint block for `src/core/**/*.test.ts`.
3. **Edits went through Python/sed scripts, and the worktree guard refused heredocs and chained git commands** (9 refusals across the two sessions). "Use the Edit tool" in the briefs didn't change behaviour, because files were read with `cat`. **Done:** concrete rules in CLAUDE.md and the brief (Read before Edit; one git command per Bash call; `git commit -F <file>`).
4. **`git commit --no-edit` after a merge with conflicts dropped the trailers** (3 times in the run, each amended afterwards). **Done:** the brief now says `git merge --no-commit`, then `git commit -F`.
5. **`isolation: "worktree"` worktrees started from origin's default branch, not the integration tip.** Each implementer reset its worktree, costing about 30 seconds each. Kept the reset step in the brief.
6. **The integration branch moved mid-ticket, so tickets touching the same core files needed repeated merges.** **Done:** the brief advises running frontier tickets that share core files one after another.
7. **ESLint lets `item` through in core identifiers,** although the glossary avoids it. **Not done:** M1 code uses it widely, so a rename pass would have to come first.

## Corrections to the coordinator's premise

- The raw `repeat.rrule` assertions came from #25–#27, not #29.
- The fixer's 22 minutes were seven separate items. Its own run had little friction.
